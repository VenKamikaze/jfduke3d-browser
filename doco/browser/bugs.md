# Lesser bugs in the original game

Bugs found in upstream jfduke3d, jfbuild, jfaudiolib or vnet (at the pinned commits) while doing the browser work that **don't break the game**, or that break it only **in a feature a normal multiplayer game is unlikely to use** (marked **not planned**). Game-breaking, reproducible bugs get their own fix brief instead (see "Bugs found in the original game" in [`README.md`](README.md)). Nothing here has been sent upstream.

Each entry: where, what happens, how it was found, and its state (**open**, **worked around** in a brief, **fixed** on a `fix/` branch, or **not planned**).

**Numbering.** The engine forks (jfbuild, jfaudiolib, jfmact) and vnet are shared with Shadow Warrior, and so are their bugs: those keep jfSW's **L-numbers**, which live in [`jfsw-browser`'s `doco/browser/bugs.md`](https://github.com/VenKamikaze/jfsw-browser/blob/claude/doco/browser/bugs.md) (L1 to L34 at the time of writing; for example L9 stale `libengine.a`, L10 `syncstate`, L15 `ar rc`, L18 a lost relay session, L24/L33 refused pointer lock, L31/L34 vnet's WebTransport). Don't copy them here; add a line below only when a Duke brief meets one and has something to say about it. Bugs in **Duke's own code** get **D-numbers** (D1, D2, …) in the table below, so the two sets never collide. (This split is the implementer's choice in brief 00; the coordinator may change it.)

## Found in brief 03 (D15 and up)

| D15 | `src/duke3d.h:120` (`RANDOMSCRAP`) and about 25 other calls, e.g. `src/actors.c:578`, `:632`, `:1782`, `:3502`, `:3539`, `src/game.c:9960-10086` (glass), `src/sector.c:2017-2064`, `src/gamedef.c:2729-2731`, `src/player.c:139` | **Game-breaking for games between a native (gcc) build and the browser (clang); reproduces; needs its own brief.** The C standard does not say in which order the arguments of a call are evaluated, and these calls have several arguments that are each a call of the game's random number generator: `EGS(sect, x+(TRAND&255)-128, y+(TRAND&255)-128, z-(8<<8)-(TRAND&8191), SCRAP6+(TRAND&15), ..., TRAND&2047, (TRAND&63)+64, -512-(TRAND&2047), ...)` (`TRAND` is `krand()`). **gcc (x86-64) evaluates them right to left, clang left to right.** The generator is called the same number of times either way, so the seed stays equal, but each argument gets another random number: scrap, glass, gibs, bubbles and the loot of a crate fly differently, in sprites that the simulation then moves and that can hit things, so the machines drift apart (and desync). Found by the native-against-wasm determinism test: a native (gcc) playback and the wasm one of the same demo first differ at **tic 210** (sprites, hittype), 65 sprite and hittype entries, nearly all scrap (pictures 2391 to 2405, `SCRAP6` and its neighbours), with other `x`, `y`, `z`, `ang`, `xvel`, `zvel`; a **clang-built native game is identical to the wasm one for all 1990 tics**, and differs from the gcc-built native game at the same tic. Native builds made with different compilers (gcc on Linux, MSVC on Windows, clang on macOS) would probably disagree in the same way (not tried). | 03: `tests/web/determinism.js` | **open**, not fixed. Upstream `jonof/jfduke3d` `HEAD` is still `55c5f95` (checked 18 Nov 2026, `git ls-remote`), so it is not fixed there. Fixing it means hoisting each argument's random call into a local in a fixed order (the order is a decision: gcc's, right to left, keeps today's native games and demos as they are; the original DOS compiler's is not known here), in each of the calls (an audit of every call with two or more `krand()`/`TRAND`/`rnd()` in its arguments, also in CON-driven code; the 25 or so found by grep are listed by `grep -nE "(TRAND\|krand\(\)).*,.*(TRAND\|krand\(\))"`). It changes the simulation, so it comes with the demo and determinism checks of the fix rules in `README.md`. Until then `determinism.js` marks "gcc native against wasm" a known failure (`KNOWN.D15`) and checks wasm against a clang-built native game. |
